# Customer-bound Dodo Test checkout (Stage 2B-1)

`POST /api/billing/dodo/customer-checkout` is disabled unless `DODO_TEST_CUSTOMER_CHECKOUT_ENABLED=true`. It additionally requires the existing founder test cookie and a valid server-side Google session. It derives the email and subscriber identity from that session; request bodies cannot select an email, product, subscription, or customer.

The route creates a 256-bit opaque checkout reference, persists only an HMAC of it with the authenticated subscriber and a seven-day pending-status window, and sends the raw reference as `metadata.cliponaut_checkout_ref` on Dodo's documented checkout request. The correlation is marked with the returned checkout session ID only after a successful provider response. The recorded provider checkout-session ID is retained for delayed signed webhooks even after the UI pending window expires.

The current official Dodo TypeScript schema documents checkout `metadata` as **payment** metadata. It also documents signed `payment.succeeded` data as a `Payment` with `payment_id`, `checkout_session_id`, `subscription_id`/`subscription_ids`, `business_id`, `brand_id`, and metadata. Subscription lifecycle webhooks carry the authoritative subscription ID, product ID, brand, and current status. Stage 2B-1 binds only when those two signed event records agree on the provider subscription ID and the payment checkout-session ID exactly matches a server-created correlation for the authenticated customer. It never uses payment email, redirect parameters, or metadata propagation as ownership proof.

No provider API read is required for normal signed event delivery. The existing key's **Payments Read** permission is sufficient only for a future recovery/reconciliation read of `GET /payments/{payment_id}`; no new Dodo key or permission is needed. A real Test Mode confirmation is still required before enabling checkout: verify a genuine `payment.succeeded` contains the documented checkout/subscription identifiers and that it joins the later signed subscription lifecycle event as expected. Public checkout, entitlements, quotas, Live Mode, and payment success claims remain disabled.
